# Ping v1 contract

Source of truth for what we build now. [PRD.md](PRD.md) is the original brief; [sketches/](sketches/) are visual reference only.

**Product:** a private two-person household note/task **queue** (a couple). Not a social feed, not a team tool.

**Visuals:** take card language, branding, and motion from the newer sketches. Ignore: bottom nav, Search / Notifications / Settings, images, checklists, titled posts, three named authors, “Contact Support.”

## Household

The whole app **is** the household. There is no `households` table in v1.

- Assume only two people will have Clerk accounts (restrict signup in the Clerk dashboard: invitations / allowlist).
- Signed out → Access Restricted + Sign In (same `/` route, no redirect loop). Sign-up is disabled in the UI; invite users from the Clerk dashboard.
- Signed in → member. Private notes are scoped by `author_id`, not by membership rows.
- A third signer would see shared pings; do not solve that until we expand.

Author chrome: **Me** / **Partner** (Hebrew: **אני** / **פרטנר**), plus Clerk avatar. No local profile system.

## A Ping

| Field | Rule |
| --- | --- |
| `id` | UUIDv7 |
| `author_id` | Clerk user id |
| `body` | Plain text (required) |
| `is_private` | Boolean. Partner never sees it |
| `priority` | Token: `urgent` \| `idea` \| `routine` (default `routine`) |
| `tags` | 0..n tokens from the static list below. DB stores tokens only |
| `target_date` | Optional **date** (no time), stored as a date |
| `resolved` | Boolean. Resolved pings stay in All if their date is still in the future, or if `completed_at` is within the last 24 hours |
| `completed_at` | timestamptz UTC, set when resolved, cleared when restored |
| `created_at` | timestamptz UTC |
| `updated_at` | timestamptz UTC |

No title, images, checklists, or rich text in v1.

**Tag tokens:** `groceries`, `home`, `medical`, `work`, `travel`. Labels live in the translation dictionary.

## Screens

In: signed-out gate, main feed, add/edit sheet (bottom sheet on mobile, modal on desktop).

Out: Search, Notifications, Inbox, Settings routes. Theme and language stay in the header.

## Permissions

- Create: any signed-in user.
- Edit / delete: **author only**.
- Resolve / unresolve a **shared** ping: either person.
- Resolve / unresolve a **private** ping: author only.
- Overflow menu: Edit, Resolve or Restore, Delete (Delete only for author).

## Feed, filters, sort

**Default ("All"):** pings the viewer may see (shared from both + **my** private) that are unresolved, still dated in the future (even if already resolved), or resolved in the past 24 hours (`completed_at`). Resolved items render as completed.

**URL search params** (filters of different types AND; same type OR):

- `tag` — one or more tag tokens
- `priority` — one or more priority tokens
- `private=1` — only my private pings
- `resolved=1` — only resolved pings (Done)

“All” chip clears those params. Chip clicks are links that change the URL; the loader re-queries. No client cache for server data.

**Sort:** Urgent first, then `target_date` ascending (nulls last), then `created_at` descending.

**Dates:** format on the server with `Intl` using the app locale (`ping-locale` cookie). `target_date` is a calendar date, not a timezone instant.

## Sync

No WebSockets, no polling. The feed is fresh on load and on navigation after a mutation (`router.invalidate`). Optional later: invalidate on tab focus.

Client `useState` is allowed for chrome (sheet open, form fields, menus). It is not allowed as a cache for ping lists.

## Empty states

- No pings yet: prompt to add one.
- Filters match nothing: say so; keep filter chips visible.

## Deploy / PWA

Keep the current Nitro host. Manifest + install icons are enough; no offline service worker in v1.
